Guide · Learning with Tutor MCP

Use the tutor as a learning engine.

Tutor MCP is not another chat prompt. It is the durable layer between you and an AI: explicit signals for what should happen next, plus narrative memory for what you actually went through.

Model

Engine vs AI

The AI is the interface: it explains, asks questions, adapts tone, writes examples and summarizes the session. Tutor MCP is the engine: it stores state, chooses the next activity, validates evidence, detects gaps and decides when to review or move on.

The useful split: Tutor MCP decides what and why. The AI decides how to say it.
Start

First session

Start with a goal concrete enough to decompose into concepts. The assistant creates a domain if none exists, diagnoses your starting point and proposes the first activity.

Use Tutor MCP.
I want to learn Go concurrency in three weeks.
Create a learning domain, start with a short diagnostic, and keep session memory enabled.

A good first run calls init_domain, then get_next_activity. If the assistant skips the engine and starts tutoring directly, ask it to use Tutor MCP explicitly.

Start

In Tutor ACP

Open Formations to choose a programme from your institution’s catalogue, or write what you want to learn in Conversation when your institution allows personal programmes. The programme is saved from the first exchange and can be resumed later.

  • Conversation shows each tool call as it happens and asks for your decision when a tool needs permission. Interrupted answers stay marked as such.
  • Formations lists your programmes and the catalogue, with concepts, prerequisites and progress. Owners and authorised trainers edit programmes here, manually or with the agent.
  • Settings keep your agent, institution, members, language, theme and reading preferences per account.

If setup is incomplete, your message is kept as “À envoyer” (to send) until both connections are ready.

Your moves

Ask for what you need

You do not have to accept the default path silently. Ask for a review, a different pace, a harder challenge, a safer exercise, another style or a visible explanation of the plan. The assistant should use learning_negotiation, transfer_challenge, feynman_challenge or get_olm_snapshot rather than inventing a plan from scratch.

Use Tutor MCP.
Show me why you picked this activity in plain language.
Then offer one easier option, one harder option, and one review-only option.
Prompts

Prompt examples

These name the engine explicitly so the assistant calls the tools instead of improvising a normal tutoring chat.

Start a new goal

Use Tutor MCP.
I want to learn SQL window functions for analytics interviews in two weeks.
Create the domain, start with a diagnostic, and keep the first exercise short.

Resume where you stopped

Use Tutor MCP.
Resume my Go concurrency track from the last session.
Read my learner context and memory before choosing the next activity.

Ask for review instead of new material

Use Tutor MCP with review intent.
Pick the concept most at risk of forgetting and give me one calibrated exercise.
Record the result after I answer.

Change the teaching style

Use Tutor MCP.
Keep the same activity, but teach it Socratically.
Ask one question at a time and do not reveal the answer until I try.

Make the plan transparent

Use Tutor MCP.
Show me why this activity was selected in learner-friendly terms.
Then offer one safer option and one harder option.

Correct memory

Use Tutor MCP.
You remembered that I prefer visual explanations, but that is only true for math.
Update learner memory so programming sessions use concrete code examples first.
End

Close a session

A clean close preserves continuity. The engine returns a recap and asks the AI to write the session summary through update_learner_memory. It can also record an if-then commitment for the next session.

Close the Tutor MCP session.
Summarize what changed, ask me when I will practice next, and save the session memory.
Under the hood

Conversation loop

get_learner_contextOpen with context. Active domains, recent history, concept states and active misconceptions, before tutoring.
get_next_activityLet the engine choose. Phase, concept, activity, difficulty target, motivation brief and relevant memory, with a recorded decision contract.
record_interactionRecord the outcome. Success, error type, hints, initiative and interpretation notes. Evidence-bearing answers go through a frozen assessment attempt.
record_session_closeClose cleanly. Recap signals and a memory-writing request so the AI stores a factual session summary.
The loop only works if outcomes are recorded. If the assistant gives exercises but never calls record_interaction, the engine cannot update estimates, retention or misconceptions.
Signals

Progression signals

Explicit models keep the schedule rigorous; the memory layer gives the AI enough context to avoid generic teaching. Each signal is shown with its threshold and its source. An estimate is not mastery.

SignalSourceLearner-facing effect
MasteryBKT, evidence gatesWhether a concept is ready, shaky or needs stronger proof. Estimated, retained and demonstrated are kept apart.
RetentionFSRS-5When to review before forgetting becomes expensive.
StructureKST, prerequisitesWhich concepts can unlock without skipping foundations.
Transfernear · far · debugging · teaching · creativeWhether knowledge moves beyond the training pattern.
Metacognitionaffect, calibrationHow much support, prediction or reflection the tutor should propose. Descriptive, not a validated autonomy score.
Narrativesessions, concept notes, archivesWhat happened, what clicked, what remains uncertain and what to verify.
Memory

Learner memory

Narrative memory is designed for factual summaries, not diary prose. Sessions capture what happened; concept notes track durable observations; pending memory holds unconfirmed hypotheses; archives consolidate longer periods. In the local, hobby and institution profiles it is stored encrypted and versioned in the database.

get_memory_state
read_raw_session(timestamp: "2026-10-14T16:30:00Z")
update_learner_memory(scope: "concept", concept_slug: "goroutines",
                      operation: "replace_section", section_key: "Current state", content: "...")

Ask the assistant to mark uncertain observations as hypotheses. Tutor MCP exposes pending memory so the AI can use it without treating it as established truth.

Operate

Privacy and backups

Your AI provider or local client keeps its own chat transcript. Tutor MCP keeps the learning state you preserve through MCP calls, in the installation you chose. For local and hobby profiles, back up the whole profile directory, including runtime.db and keys.json, with every process stopped. Institutions keep PostgreSQL procedures and separate server-key backups; members keep their own encrypted identity backups.

For sensitive use, self-host behind HTTPS, restrict TRUSTED_PROXY_CIDRS and review what the AI writes to memory from time to time: it is meant to be readable. See backup and restore.
