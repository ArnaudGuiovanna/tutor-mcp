02 · Two parts, one learning journey

The application and the engine.

Tutor ACP is the desktop application for conversations, courses and institutional settings. It includes the Codex and Claude adapters; their provider connection remains separate from your Tutor membership.

Tutor MCP is the learning service. It keeps the programme, learning evidence and review schedule so you can return to your course. You can run it locally, host a hobby service or operate an institution.

Continue with the same Tutor installation to retain the same server-side learning history. A different installation does not automatically receive your profile.

04 · Connect

Keep the connections clear.

In Tutor ACP, choose Codex or Claude and connect through the provider’s supported account workflow. Then connect Tutor with your local profile or institution identity. Provider access and any related costs remain separate.

If you already use Claude Code, Claude Desktop, Hermes or another compatible MCP client, connect the Tutor MCP server directly. Local desktop and command-line clients can start it over stdio.

Cloud-based clients need a compatible public HTTPS service. The hobby OAuth connection and the native institution identity workflow are different: use the setup for your actual profile.

05 · Check your setup

Make the first session count.

  1. Confirm that your agent and Tutor connections are ready.
  2. Choose a course you can access, or create a personal programme if your institution allows it.
  3. Complete an activity and ask the tutor to save a session summary and next step.
  4. Reopen the same account and course, then ask to continue.

If a connection or permission blocks the journey, follow Troubleshooting. For a guided example, read Your first practical session.

06 · Look after your learning

Keep a way back.

Your identity export, desktop conversations and service database are different backups. Save your encrypted identity before you need recovery, and protect the data you operate before a software upgrade.
